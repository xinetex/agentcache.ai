## Verified in this worktree

- MCP manifest execution actions include authentication expectations and disclose that starting a run does not call an external provider.
- API discovery returns the execution route catalog, including admin-only gate decisions.
- Context-pack and run creation use authenticated principal/organization context, not request-body organization claims.
- Common credential fields and recognizable token strings are redacted before context/run persistence and receipt construction.
- Contract and unit tests cover manifest/catalog discovery, ownership isolation, policy denial, gate flow, key fail-closed configuration, and redaction behavior. Reviewer authorization also rejects the owner, requires same-organization membership, and prevents one reviewer identity from filling multiple roles.
- Connection service coverage verifies authenticated encryption/decryption, owner isolation, key rotation, and revocation; contract coverage verifies provider credentials are not returned and another API principal cannot list or revoke them.
- Jetty adapter unit tests verify fixed provider URLs, service-key header use, aggregate-only output, and invalid-key rejection; contract tests verify an unregistered delete action is denied and written to invocation history.
- Invocation service tests verify durable lifecycle updates, principal-isolated history, and usage counting that excludes denied, failed, and incomplete actions from candidate billable units.
- Customer route contract tests cover Audio1 CDN, transcode, and transcribe request validation; ClawSave and Helix Hono mounts; Jetty provision, edge, and chunk-cache aliases; and the direct Vercel Jetty handler exports. These use stubs/mocks and do not prove production routing or provider/database behavior.

## Build order from this inventory

1. **Partial:** individual reviewer identity, same-organization membership, owner separation, and distinct reviewers across required roles are enforced. Map workflow labels to directory roles; the gate's operator display label is still user-supplied, while the authenticated admin credential is the authoritative actor identity.
2. **Implemented in code, deployment pending:** establish owner-controlled connections and application encryption. Apply migrations 0005–0019 and configure the key before real credentials. Platform admins can configure a time-bounded action budget; provider attempts reserve atomically, including failed provider attempts, while policy-denied requests and idempotent replays do not consume the cap.
3. **Pilot slice implemented:** the fixed Jetty adapter checks ownership, read scope, context-pack allowlisting, run state, and policy; calls have bounded timeouts and aggregate-only outputs. Fixed-action invocation idempotency and policy evidence (version, evaluated rule IDs, score) are implemented. Completed-call replay is subject to current run, policy, owned-connection, and scope checks; expired or revoked connections cannot replay stored results. Generic multi-tool idempotency and versioned action-policy definitions remain open.
4. **Partial:** invocation rows, decision metadata, and active execution-control records are durable SQL records; connection-recovery and shared receipt source-of-truth migration plus reconciliation remain open.
5. **Implemented in code, live verification pending:** API, MCP, and console expose the Jetty summary workflow and redacted invocation history.
6. **Measurement implemented, commercial proof open:** the usage endpoint reports outcomes without charging. Validate paid demand, delivery cost, and margin with external prospects before enabling Stripe metering.

## Pilot contract evidence

- The selected adapter uses `../jettythunder-v2/server/routes/agent-storage.ts`: its service-key middleware authenticates a hashed, active, unexpired key, then reads quota and file metadata for the key's associated user/tenant. The adapter calls only fixed GET paths and returns aggregate counts; live credentials are not available in this workspace.
- The adjacent `../jettythunder-v2/server/routes/agentcache.ts` route resolves a Bearer request's user from `req.body.userId` or defaults to user `1`; do not use it as an ownership proof.
- The Audio1 transcoder's AgentCache integration at `../audio1.tv/services/transcoder/src/agentcache-integration.js` can fall back to a mock client when `AGENTCACHE_API_KEY` is absent. A mock-path success is not pilot evidence.
- These observations do not rule out a media workflow. They mean the pilot must use an authenticated provider action, real test asset/account, and independent result verification; current repo contracts do not establish those prerequisites.

## Limits of current redaction

Run/context redaction handles sensitive field names and common recognizable token formats. It cannot prove an arbitrary secret was not placed in an innocuous field or encoded form. Connection credentials are stored encrypted with an application key, but deployment configuration, migration, recovery, and operational rotation need verification. Use connection references in workflow inputs; never put provider credentials in general payloads.
