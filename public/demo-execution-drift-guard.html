A read-only action, governed from connection to evidence.

The first AgentCache execution slice reads aggregate JettyThunder storage quota and file count. It demonstrates owned credentials, an allowlisted action, an approval gate, and a useful record of what happened.

Open Agent Execution Plan a design-partner pilot

One guided path

Connect → constrain → approve → inspect

  1. 01 · Workspace

    Use an individual or organization API key

    Connect in Agent Execution. The key is kept in this browser tab and sent to AgentCache for authenticated requests.

  2. 02 · Owned account

    Save a JettyThunder service key

    Enter it in the connection form and request storage.read or metadata.read. AgentCache stores it encrypted; the connection remains unverified until the first provider call.

  3. 03 · Policy

    Create the narrow storage-summary workflow

    The context pack allows only jetty.storage.summary. File reads, downloads, writes, and deletes are outside the pilot.

  4. 04 · Approval

    Pause for a separate organization approver

    The run waits at its human gate. A different owner or administrator member approves it before AgentCache contacts JettyThunder.

  5. 05 · Governed call

    Read aggregate quota and file count

    AgentCache checks run approval, connection ownership, declared read scope, context-pack rules, and the configured action budget before the fixed provider call.

  6. 06 · Evidence

    Review outcome and disconnect safely

    Inspect the policy result, approval, actor, status, and redacted aggregate output. Disconnecting revokes the connection and clears its stored credential material.

Acceptance checks

  • • An approved read completes and appears in run history.
  • • A disallowed action is blocked before provider traffic and recorded.
  • • Expired credentials, provider errors, and incomplete evidence stay visibly distinct.
  • • Returned records and logs contain no provider key or file identifiers.

What has and hasn’t been verified

The repository contract suite exercises the API with a provider stub. It does not prove a live JettyThunder connection or a deployed database schema.

Run the live acceptance checks in a Vercel Preview environment with an isolated test database, a Preview-only encryption key, and a dedicated JettyThunder test account. Do not use production credentials for the demo.
